Заметки по реализации:
- Пути треков в клипах — от корня сцены (root_node плеера `..` = Skeleton);
  тест `tests/smoke_skeleton_anim.gd` резолвит их так же, как движок.
- Клипы добавляются через `AnimationLibrary` (в Godot 4 у AnimationPlayer
  нет `add_animation` вне библиотеки).
- Тайминги боя по-прежнему только в экспортах `skeleton.gd`: клипы
  подгоняются через `speed_scale = длина_клипа / нужная_длительность`.
- Смерть: `_die()` гасит Hitbox (`deactivate()`), играет `death` 0.6 с,
  удаляет узел по таймеру; спавнер считает живых по дереву — безопасно.

---

Цель: скелеты (мечник и лучник) — шарнирные «куклы» из частей тела
(череп, рёбра, таз, 2 руки, 2 ноги), с читаемыми анимациями:
покой, ходьба, замах/удар (лёгкий и тяжёлый), блок щитом,
натяжение лука, стаггер, смерть. Стиль анимации — SaS:
долгая читаемая подготовка (anticipation), резкий удар,
медленное восстановление (recovery = окно наказания).

Эталон поведения уже заложен в коде: AttackPhase WINDUP → HIT → RECOVERY
(scripts/skeleton.gd, Фаза 7). Анимации синхронизируются с этими фазами.

## Этап B. Риг-сцена `data/world/skeleton.tscn`

Иерархия пивотов (по образцу player.tscn):

```
Skeleton (CharacterBody2D, skeleton.gd)
├── Hurtbox (было)
├── Visuals (переворот scale.x = facing)
│   └── Rig
│       ├── Hips (пивот таза)
│       │   ├── Pelvis (Sprite2D)
│       │   ├── Spine (пивот) → Ribcage (Sprite2D)
│       │   │   └── Neck (пивот) → Head (Sprite2D sk_skull)
│       │   ├── ShoulderBack → UpperArmBack → ElbowBack → ForearmBack → HandBack → Shield (щит в левой)
│       │   └── ShoulderFront → UpperArmFront → ElbowFront → ForearmFront → HandFront → Sword (Sprite2D)
│       │        └── Hitbox (Area2D, HitboxShape по клинку)   ← путь меняются!
│       ├── ThighBack → ShinBack → FootBack
│       └── ThighFront → ShinFront → FootFront
│       (у лучника: HandFront → Bow + Bowstring)
├── AnimationPlayer (анимации генерируются кодом, см. этап C)
└── HealthBar/HealthLabel (как сейчас, генерируются из кода)
```

Важно: `Hitbox` — потомок меча, поэтому анимация руки двигает
форму удара: урон «летит» вместе с клинком, как у игрока.
Пути в skeleton.gd обновляются: `Visuals/Rig/.../Sword/Hitbox`.

## Этап C. Анимации — генерация кодом (`scripts/skeleton_animations.gd`)

Решение: библиотека анимаций строится из GDScript, а не пишется
в .tscn — проще поддерживать и править кривые (вручную tscn-анимации
на десятки треков писать надёжнее кодом).

Анимации (все крутят rotation/position пивотов Rig):
- `idle` — дыхание: микро-подъём груди/головы, руки чуть качаются;
- `walk` — цикл шагов: противофазные ноги, покачивание корпуса,
  speed_scale привязывается к скорости (как у игрока);
- `light_windup` — короткий занос меча назад-вверх (0.4 с);
- `light_swing` — резкий горизонтальный рубящий взмах (0.12 с, совпадает с HIT);
- `heavy_windup` — длинный замах над головой, корпус отклоняется назад (0.6 с);
- `heavy_swing` — рубящий сверху вниз, корпус наклоняется вперёд;
- `block` — мечник поднимает щит перед собой (поза, не цикл);
- `bow_draw` — натяжение тетивы (поза, держится до выстрела);
- `bow_release` — отпускание, короткая отдача;
- `stagger` — подселивание, голова вниз, руки опускаются;
- `death` — падение в кости (распад: части разлетаются) — опционально;
- `RESET` — все пивоты в 0 (страховка, как у игрока).

Длительности windup/swing задаются из skeleton.gd через speed_scale,
чтобы экспорт-параметры Фазы 7 (light_windup_sec и т.д.) остались
единственным источником правды для таймингов.

## Этап D. Интеграция в `scripts/skeleton.gd`

- `@onready` на все пивоты + `animation_player`;
- `_play_anim(name, custom_speed)` — общий плеер с фолбэком на RESET;
- locomotion: idle/walk по `absf(velocity.x)` (порог ~5), speed_scale
  пропорционален скорости;
- синхронизация с фазами атаки:
  - `_begin_melee_attack()` → `light_windup`/`heavy_windup` (speed_scale
    подгоняет длину под экспорт-таймер), подсветка клинка остаётся;
  - `_swing_sword()` (фаза HIT) → `light_swing`/`heavy_swing`;
  - RECOVERY → доснять последнюю и `idle`;
- стаггер: `poise.stagger_started` → анимация `stagger`, конец → idle;
- мечник в простое ближе к игроку держит `block` на короткое время
  после полученного блока — опционально (Этап F);
- лучник: перед `_shoot_arrow()` → `bow_draw` (пауза = время натяжения,
  новая экспорт-переменная draw_time 0.5 с), затем выстрел + `bow_release`;
- смерть: проигрываем `death` ~0.6 с, потом queue_free (таймер);
- тесты: smoke_telegraph трогает weapon_hitbox/sword_visual напрямую —
  обновить под новые пути/типы (Sword станет Sprite2D).

## Риски и решения

- **Объём ручной работы с кривыми** → генерация анимаций кодом
  (Этап C), ключи считаются формулами (синусы/линейные ease).
- **Hitbox вне клинка при рассинхроне** → HIT-фаза и swing-анимация
  одной длины; activate() вызывается в начале swing, как сейчас.
- **Переворот scale.x зеркалит анимации** — это корректно (как у игрока).
- **Спавнер** (skeleton_spawner.gd) инстансит skeleton.tscn — сцену
  меняем на месте, спавнер не трогаем.

## Ожидаемый результат

Скелет в стиле SaS: идёт шаркающей походкой, замирает в длинном
красном замахе перед тяжёлым ударом, рубит с разворота, мечник
закрыт щитом со спины-сбоку, лучник заметно натягивает тетиву,
в стаггере оседает. Всё читается глазу и согласуется с окнами
парирования/ролла из фаз 1–2 и 7.
